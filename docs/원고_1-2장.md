## Ⅰ. 제안 배경 및 문제 정의

### 1. 제안 배경

**가. 인기 도서 편중 이용과 잠자는 도서의 발생**

공공도서관은 다양한 주제와 수준의 장서를 보유하고 있으나, 실제 대출은 베스트셀러와 신간 등 일부 인기 도서에 집중되는 경향을 보인다. 그 결과 주제 관련성과 정보 품질이 높음에도 이용률이 낮아 이용자와 만나지 못하는 도서, 즉 '잠자는 도서'가 다수 발생한다. 실제로 서울 남산도서관과 부산 다대도서관은 각각 62,480권, 64,970권의 대출 0회 도서를 보유한 것으로 보도된 바 있어¹, 이는 특정 도서관의 예외적 현상이 아니라 장서 운영 전반에서 반복되는 구조적 문제임을 보여준다.

**나. 익숙한 도서를 반복하는 추천 방식의 한계**

기존 도서 추천 서비스는 대체로 이용자의 대출·검색 이력을 기반으로 유사 도서를 반복 제안하는 방식에 의존한다. 이 방식은 이용자가 이미 알고 있는 주제·저자의 범위를 벗어나기 어렵게 만들며, 정확한 서명이나 저자를 모르는 이용자가 방대한 장서 속에서 새로운 관심 도서를 스스로 찾기는 더욱 어렵다. 탐색의 진입 장벽을 낮추면서도 관심사를 새로운 주제로 확장하는 발견 경험이 요구된다.

**다. 저이용 장서 활용에 따르는 사서의 업무 부담**

사서는 도서관별 장서·대출 데이터를 검토해 전시 후보 도서를 선정하고 소개 문구를 작성하는 업무를 반복적으로 수행한다. 그러나 이 과정은 대부분 수작업에 의존하며, 도서관마다 정형화된 형태로 반복됨에도 이를 지원하는 도구는 마련되어 있지 않다.

### 2. 문제 정의

공공도서관은 장서·대출 데이터를 지속적으로 축적하고 있음에도, 이를 이용자의 새로운 도서 발견과 사서의 큐레이션 업무에 연결하는 체계는 부재하다. 용인시 '히든북스'(2025, 17개소 종합자료실에서 전년도 대출 0회 도서를 최대 7권까지 추가 대출)²나 인천 연수구 '잠자는 책을 깨워라'(2024, 7개 구립도서관에서 미대출 도서를 포함한 대출 이벤트로 기념품 제공)³와 같은 대응은 한시적 대출 유도 행사에 머물러 지속적인 탐색 경험으로 이어지지 못하며, 국립중앙도서관 'AI실감서재'(2025)는 서울 소재 디지털도서관 현장에서 AI 사서를 통한 개인 맞춤형 추천과 스마트 책장 탐색을 제공하는 체험형 서비스로, 특정 물리 공간을 전제로 하여 저이용 장서 발굴과 사서 큐레이션 관리 기능은 제공하지 않는다⁴. 즉, 데이터 기반으로 저이용 도서 후보를 상시 산출하고, 이를 이용자 맞춤 추천과 사서 큐레이션 제작까지 하나의 흐름으로 연결하는 온라인 서비스는 확인되지 않는다.

### 3. 제안 개요

본 프로젝트 WakeBook은 이용자에게 익숙한 인기 도서를 탐색의 출발점으로 제시하고, AI가 추출한 핵심 키워드에 독서 목적·분위기를 결합하여 도서관별 장서 대출 데이터에서 선별한 잠자는 도서를 추천한다. 동시에 사서에게는 저이용·고품질 도서 후보군을 자동 산출하고 전시 큐레이션 초안을 생성하는 기능을 제공하여, 이용자의 새로운 발견 경험과 사서의 장서 활용 업무를 하나의 서비스 구조로 통합한다.

## Ⅱ. 활용 데이터 및 분석 설계

### 1. 활용 데이터 개요

WakeBook은 도서관 공공데이터를 핵심 축으로, 민간 서점 API를 보조 데이터로, AI가 생성하는 파생 데이터를 결합해 서비스를 구성한다.

**가. 도서관 정보나루(data4library) 공공데이터 — 핵심 데이터**

도서관정보나루가 제공하는 인기대출도서 조회, 도서 상세조회, 소장·대출가능 조회 API와, 도서관·월 단위로 내려받는 장서 대출목록(오픈데이터)을 활용한다. 이 중 장서 대출목록은 도서관별 개별 도서의 대출 건수를 담고 있어, 저이용 도서 후보군을 산출하는 유일한 근거 데이터로 사용된다.

**나. 알라딘(Aladin) Open API — 보조 데이터**

목차 정보는 도서관·공공데이터에서 안정적으로 제공되지 않아, 민간 서점의 알라딘 Open API(`ItemLookUp`)를 보조적으로 연동해 도서 소개 정보를 보강한다. 공모전이 요구하는 도서관 데이터 활용 요건은 정보나루 데이터로 이미 충족되며, 알라딘 데이터는 이용자 화면의 정보 품질을 높이는 용도로만 곁들인다.

**다. AI(OpenAI) 기반 파생 데이터**

정보나루 원천 데이터만으로는 이용자가 이해하기 쉬운 키워드, 추천 근거, 큐레이션 문구가 만들어지지 않는다. WakeBook은 도서 상세정보(책 소개, 서명, 저자)를 프롬프트로 구성해 OpenAI API로 핵심 키워드, 추천 이유, 도서 간 비교 설명, 큐레이션 제목·소개문·해시태그를 생성한다. 이 파생 데이터는 원천 데이터가 아니라 원천 데이터를 이용자가 활용 가능한 형태로 가공한 결과라는 점에서 알고리즘 설계의 핵심에 해당한다.

### 2. 데이터 처리 및 분석 설계

**가. 잠자는 도서 후보군 산출**

정보나루는 도서관별 대출 통계를 실시간 API가 아닌 월 단위 오픈데이터 파일로만 제공한다. 이에 사서가 자신이 속한 도서관의 장서 대출목록 CSV를 직접 내려받아 업로드하면, 서버는 대출건수 하위 도서를 대출건수 오름차순으로 정렬한 뒤, 도서 상세조회 API로 출판사·발행연도·표지·책소개 등 정보 품질을 하나씩 검증해 후보군 상한(기본 30권)을 채울 때까지 선별한다. 검증을 통과한 도서만 도서관 코드 단위로 데이터베이스에 저장되며, 같은 도서관의 이전 후보군은 새 업로드 결과로 전량 교체되어 다른 도서관의 후보군에는 영향을 주지 않는다.

**나. AI 핵심 키워드 추출 및 추천 점수 산출**

이용자가 인기 도서를 선택하면 해당 도서의 책소개를 근거로 AI가 5개 내외의 핵심 키워드를 추출한다. 이용자가 키워드·독서 목적·분위기를 선택하면, 서버는 도서관 코드에 해당하는 후보군 내에서 아래 가중합으로 최종 추천 점수를 산출한다.

```
최종 추천 점수 =
  키워드 관련성 × 0.45
+ 독서 목적 일치도 × 0.20
+ 분위기 일치도 × 0.15
+ 도서 정보 품질 × 0.10
+ 잠자는 도서 발견 가치 × 0.10
```

이 중 도서 정보 품질은 출판사·발행연도·표지·책소개 보유 여부를 기반으로 산정하고, 발견 가치는 후보군 내 대출건수를 최솟값·최댓값 기준으로 정규화해 대출건수가 낮을수록 높은 점수를 부여한다. 점수를 세부 항목으로 분해해 함께 제시함으로써, 추천 결과가 단순 순위가 아니라 근거를 설명할 수 있는 형태로 이용자에게 전달되도록 설계했다.

**다. 도서 비교 및 조건별 재탐색**

이용자가 기준 인기 도서와 추천된 잠자는 도서를 비교하면, AI가 두 도서의 책소개를 바탕으로 공통 키워드, 난이도, 문체 차이를 자연어로 설명한다. 또한 특정 추천 도서를 기준으로 '더 쉬운 책', '더 깊이 있는 책', '반대 관점' 등 조건을 지정해 관련 후보군 내에서 재탐색하는 기능을 제공해, 한 번의 추천에서 그치지 않고 반복적인 발견 흐름을 이어가도록 했다.

**라. 사서 큐레이션 초안 생성**

사서가 대시보드에서 전시 주제, 대상 연령, 분위기, 제외 키워드 등을 입력하면, AI는 해당 사서의 도서관 코드에 연결된 후보군 안에서 조건에 맞는 도서를 선정하고, 전시 제목·소개문·해시태그와 도서별 추천 이유를 함께 생성한다. 이 초안은 저장되기 전까지 임시 결과이며, 사서가 검토 후 공개 여부를 정해 저장하면 이후 목록에서 수정·삭제할 수 있다.

```

                          |

                          |

                          |
        +----------------+----------------+
        |                                 |
[이용자] 인기 도서 선택                     [사서] 전시 주제 입력
        |                                 |
   AI 핵심 키워드 추출                 AI 큐레이션 초안 생성
        |                                 |
 키워드·목적·분위기 선택            (제목·소개문·해시태그·도서 목록)
        |                                 |
   추천 점수 산출(가중합)                  사서 검토 후 저장
```

### 3. 분석 설계의 특징과 향후 보완

이 설계는 두 가지 특징을 가진다. 첫째, 추천 점수를 세부 항목으로 분해해 제시함으로써 결과에 대한 신뢰를 높이는 설명 가능한 추천 구조를 갖췄다. 둘째, 후보군을 도서관 코드 단위로 완전히 분리해 관리함으로써, 여러 도서관이 동시에 서비스를 이용해도 각자의 장서 데이터만으로 독립적인 추천·큐레이션이 이루어지도록 했다.

다만 현재 설계는 몇 가지 보완 과제를 안고 있다. 도서 정보 품질과 발견 가치 산정 기준은 실제 이용 데이터가 충분히 쌓이기 전까지는 근사적인 휴리스틱이며, 대형 도서관의 CSV(수십만 행)를 처리할 때 소요 시간이 늘어나는 문제도 확인했다. 향후 실제 대출 데이터가 축적되면 가중치와 기준을 재조정하고, 처리 방식을 비동기화하여 대용량 데이터에도 안정적으로 대응할 계획이다.
