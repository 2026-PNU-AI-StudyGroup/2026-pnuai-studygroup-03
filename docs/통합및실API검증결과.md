## 1. 통합 원칙과 반영 범위

`origin/fix`를 통째로 병합하지 않고 현재 구현을 기준으로 필요한 변경만 수동 반영했다. 이 방식으로 기존의 KDC 균형 후보군, 실시간 트렌드, NAVER 교차 검증, 카카오 우선 도서 조회가 이전 코드로 되돌아가는 것을 방지했다.

반영한 기능은 다음과 같다.

- 도서관별 DB 잠금으로 같은 도서관의 동시 후보군 산출 요청 직렬화
- 후보군 산출 작업을 요청한 사용자만 작업 상태 조회 가능
- 사용자당 일일 산출 한도를 Asia/Seoul 날짜 경계로 계산
- 비동기 작업 큐 포화 시 작업을 `FAILED`로 기록하고 `503 JOB_005` 반환
- AI 추천·큐레이션 프롬프트에서 기존 추천 이유보다 원본 도서 소개글을 우선 사용
- 공개 큐레이션 목록·상세 API와 프론트 화면 추가
- 새 큐레이션의 공개 여부 기본값을 비공개로 변경
- MySQL 동시성 검증을 일반 테스트와 분리한 `mysqlTest` 작업 추가

다음 기존 동작은 그대로 유지했다.

- 도서 상세 공급자: **카카오 → 알라딘 → 정보나루**
- CSV의 KDC 코드 보존 및 KDC 0~9 대분류 균형 후보군
- 기본 후보군 목표 200권
- Google Trends → NAVER 뉴스·검색 추이 → OpenAI → 도서 매칭 흐름
- 홈·헤더의 `실시간 트렌드` 메뉴와 `/trends` 화면

마이그레이션 충돌을 피하기 위해 큐레이션 기본값 변경은 `V202608190002__default_curations_to_private.sql`로 추가했다.

## 3. 공개 큐레이션 실제 HTTP 검증

개발 MySQL과 분리된 H2 인메모리 DB와 랜덤 포트로 현재 애플리케이션을 실행하고 실제 TCP/HTTP 요청을 전송했다.

```http
GET /api/curations?page=1&size=9
```

```http
HTTP/1.1 200 OK
```

```json
{
  "success": true,
  "message": "요청이 완료되었습니다.",
  "data": {
    "content": [],
    "page": 1,
    "totalPages": 0,
    "totalElements": 0
  }
}
```

테스트 DB에 큐레이션을 넣지 않았으므로 빈 `content`는 정상이다. 같은 통합 테스트에서 다음 계약도 검증한다.

- 공개 큐레이션만 목록에 포함
- 공개 큐레이션 상세는 인증 없이 `200`
- 비공개 큐레이션 상세는 존재 여부를 노출하지 않고 `404 CURATION_001`

## 4. 발견된 문제와 후속 조치

### 4.1 Google Trends 원문 키워드 품질

실제 RSS 응답 10건 수집에는 성공했지만 첫 `sourceKeyword`가 `개`였다. 외부 연동 실패는 아니지만 조사·단위 표현을 트렌드로 사용하는 것은 서비스 품질상 허용할 수 없다.

다음 보완이 필요하다.

- 한 글자 키워드와 의존명사·단위 표현 제거
- `개`, `명`, `건`, `회` 등 불용어 목록 적용
- 기사 근거에서 재구성한 `displayTopic`과 핵심 개념의 최소 일치도 검증
- `displayTopic`을 한 단어 또는 짧은 명사구로 제한
- 필터를 통과하지 못하면 저장하지 않고 다음 트렌드 후보로 대체

현재 실제 응답의 `displayTopic`도 짧은 화면 주제보다 문장에 가깝다. 따라서 연결성과 JSON 계약은 통과했지만 트렌드 품질 완료 조건은 아직 통과하지 못한 것으로 기록한다.

### 4.2 개발 MySQL Flyway 체크섬 불일치

현재 `.env`가 가리키는 개발 MySQL로 애플리케이션을 시작하면 다음 검증 오류가 발생한다.

```text
Migration checksum mismatch for migration version 202608150001
Applied to database : 1671607829
Resolved locally    : 1112729758
```

이미 DB에 적용된 과거 마이그레이션 파일과 현재 저장소 파일의 내용이 달라진 상태다. 실제 스키마 확인 없이 `flyway repair`를 실행하면 안 된다.

- 폐기 가능한 개인 개발 DB라면 DB를 새로 만드는 방법이 가장 단순하다.
- 공유·보존 DB라면 적용 당시 SQL과 현재 스키마를 먼저 비교한다.
- 적용 완료된 마이그레이션 파일은 수정하지 않고 필요한 변경을 새 버전 마이그레이션으로 추가한다.
- 스키마가 현재 SQL과 완전히 동일하다고 확인된 경우에만 팀 합의 후 `repair`를 검토한다.

현재 `localhost:8080`에서 실행 중인 서버는 통합 전 실행본이라 공개 큐레이션 요청에 `401`을 반환했다. 체크섬 문제를 해결하고 현재 소스로 재시작해야 `/curations` 공개 권한 설정이 반영된다.
