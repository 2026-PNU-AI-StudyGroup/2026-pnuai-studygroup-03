# 최종보고서 기준 코드 수정 사항

## 1. 기준과 범위

- 구현 판단의 최우선 기준은 `docs/최종보고서.md`이다.
- 코드, API 명세, 기존 주석이 최종보고서와 충돌하면 최종보고서에 맞게 코드와 API 명세를 수정한다.
- 이 문서는 코드 수정 작업만 다룬다. 보고서 문구나 행사 날짜처럼 문서만의 오류는 범위에서 제외한다.
- 최종보고서에서 향후 과제로 분류한 트렌드 데이터 연동과 사서·기관 인증 강화는 현재 필수 수정 범위에서 제외한다.
- 각 항목은 구현, 자동 테스트, API 명세 동기화까지 완료되어야 완료로 처리한다.

## 2. P0: 추천 기능의 핵심 오류 수정

### [x] 2.1 추천·재탐색·큐레이션 프롬프트에 실제 책 소개 사용

> 완료: 세 서비스가 공통 소개 선택 로직을 사용하도록 수정했고, `description` 우선·`reason` 대체·`null` 미노출 테스트와 전체 백엔드 테스트를 통과했다.

**보고서 근거**

- 최종보고서 3.2절은 외부 API로 책 상세 정보를 보강한다고 설명한다.
- 최종보고서 4.1절과 4.2절은 추천 이유, 비교, 재탐색, AI 큐레이션을 제공한다고 설명한다.

**수정 전 문제**

- `HiddenBookCollector`는 책 소개를 `HiddenBook.description`에 저장하고 `reason`은 `null`로 저장한다.
- `RecommendationService`, `RecommendationExploreService`, `CurationGenerationService`는 AI 프롬프트를 만들 때 `reason`을 책 소개처럼 사용한다.
- 따라서 수집된 책의 소개가 있어도 AI에는 빈 설명이 전달될 수 있고, 추천 이유·재탐색·큐레이션 품질이 보고서 설명과 달라진다.

**수정 대상**

- `backend/src/main/java/com/wakebook/recommendation/service/RecommendationService.java`
- `backend/src/main/java/com/wakebook/recommendation/service/RecommendationExploreService.java`
- `backend/src/main/java/com/wakebook/curation/service/CurationGenerationService.java`
- 각 서비스의 관련 테스트

**수정 내용**

- AI 프롬프트용 책 요약은 `description`을 우선 사용한다.
- `description`이 비어 있을 때만 기존 `reason`을 대체값으로 사용한다.
- 두 값이 모두 없으면 빈 문자열을 사용해 `null` 문자열이 프롬프트에 포함되지 않도록 한다.
- 세 서비스가 같은 규칙을 사용하도록 중복 로직을 공통 메서드나 공통 유틸리티로 정리한다.

**완료 조건**

- `reason=null`, `description` 존재 조건에서 프롬프트에 `description`이 포함되는 테스트가 추천·재탐색·큐레이션 각각 존재한다.
- `description`이 없고 `reason`만 있을 때의 대체 동작도 테스트한다.
- 전체 백엔드 테스트가 통과한다.

### [x] 2.2 독서 시간 조건과 적합도 복원

> 완료: `SHORT`·`MEDIUM`·`LONG`·`SLOW` 계약, 프론트 선택 UI, 요청 검증, AI 프롬프트, `timeMatch`, 0.10 점수 가중치와 API 명세를 복원했고 전체 백엔드 테스트 및 프론트엔드 빌드를 통과했다.

**보고서 근거**

- 최종보고서 4.1절은 사용자가 키워드, 독서 목적, 기분, 예상 독서 시간을 입력해 추천받는다고 명시한다.

**수정 전 문제**

- `frontend/src/pages/Discover.jsx`에서 독서 시간 입력이 제거되어 있다.
- `RecommendationRequest`에 독서 시간 필드가 없다.
- 추천 프롬프트와 점수 계산에 독서 시간 조건 및 시간 적합도가 없다.
- `docs/API명세.md`도 독서 시간과 `timeMatch`를 제거한 상태이므로 최종보고서와 충돌한다.

**선행 결정**

- 구현 여부는 이미 최종보고서에 따라 확정이다.
- 코딩 전 허용 값, 화면 표시명, 책별 예상 시간 산정 기준만 한 가지 규칙으로 확정해야 한다.
- 프론트엔드, 요청 DTO, 프롬프트, 점수 계산, 응답 지표가 같은 값 체계를 사용해야 한다.

**수정 대상**

- `frontend/src/pages/Discover.jsx`
- `frontend/src/api/client.js`
- `backend/src/main/java/com/wakebook/recommendation/dto/RecommendationRequest.java`
- `backend/src/main/java/com/wakebook/recommendation/dto/RecommendationResponse.java`
- `backend/src/main/java/com/wakebook/recommendation/service/RecommendationService.java`
- 추천 컨트롤러·서비스 테스트
- `docs/API명세.md`

**수정 내용**

- 발견 화면에 독서 시간 선택 UI를 복원하고 추천 요청에 값을 포함한다.
- 요청 DTO에 독서 시간 필드와 허용 값 검증을 추가한다.
- AI 프롬프트에 사용자의 독서 시간 조건을 전달한다.
- 추천 점수에 시간 적합도를 다시 포함하고, 전체 가중치 합이 `1.0`이 되도록 조정한다.
- 응답에서 세부 적합도를 제공하는 현재 구조에 맞춰 `timeMatch`를 복원한다.
- API 명세는 코드 구현과 테스트가 끝난 뒤 최종보고서 기준으로 동기화한다.

**완료 조건**

- 독서 시간을 선택하지 않은 요청의 기본 동작과 선택한 요청의 동작이 모두 정의되어 있다.
- 잘못된 독서 시간 값은 `400` 응답으로 거절된다.
- 시간 조건이 프롬프트와 점수에 반영되는 서비스 테스트가 존재한다.
- 프론트엔드 빌드와 전체 백엔드 테스트가 통과한다.

## 3. P1: 운영 동작과 보고서 설명 일치

### [x] 3.1 큐레이션 공개 상태를 실제 공개 기능으로 완성

**보고서 근거**

- 최종보고서 4.2절은 큐레이션의 저장·수정·삭제와 공개 상태 관리를 제공한다고 명시한다.

**수정 전 문제**

- 큐레이션 생성 요청에서 `isPublic`을 생략하면 공개 상태로 저장된다.
- 수정 요청에서 `isPublic`을 생략해도 기존 값이 유지되지 않고 공개 상태로 바뀔 수 있다.
- 일반 사용자가 공개 큐레이션을 조회하는 경로가 없어 공개 상태의 실제 효과를 확인하기 어렵다.

**수정 대상**

- `backend/src/main/java/com/wakebook/curation/service/CurationService.java`
- 큐레이션 요청 DTO, 컨트롤러, 저장소 및 관련 테스트
- 공개 큐레이션을 표시할 프론트엔드 화면과 API 호출부
- `docs/API명세.md`

**수정 내용**

- 생성 시 공개 여부의 기본값을 비공개로 정한다.
- 수정 시 `isPublic`이 생략되면 기존 값을 유지하거나, 부분 수정이 아니라면 필수 입력으로 명확히 검증한다.
- 일반 사용자는 `isPublic=true`인 큐레이션만 목록·상세 조회할 수 있게 한다.
- 비공개 큐레이션이 공개 조회 API에 노출되지 않도록 권한과 조회 조건을 적용한다.

**완료 조건**

- 생성 기본값, 공개 전환, 비공개 전환, 값 생략 수정, 비공개 조회 차단 테스트가 존재한다.
- 프론트엔드에서 공개된 큐레이션만 확인할 수 있다.

**구현 결과 (2026-08-19)**

- 생성 요청에서 `isPublic`을 생략하면 애플리케이션과 데이터베이스 모두 비공개를 기본값으로 사용한다.
- 수정 요청에서 `isPublic`을 생략하면 기존 공개 상태를 유지한다.
- 인증이 필요 없는 `GET /curations`, `GET /curations/{curationId}`를 추가하고 저장소 조회 조건에서 공개 항목만 선택한다.
- 비공개 상세는 존재 여부를 드러내지 않고 `404 CURATION_001`을 반환한다.
- 프론트엔드에 공개 큐레이션 목록·상세 화면과 메뉴 진입점을 추가했다.
- 생성 기본값, 공개·비공개 전환, 생략 수정, 공개 목록 필터, 비공개 상세 차단을 단위·통합 테스트로 검증했다.

### [x] 3.2 한국 시간 자정 기준을 서버 시간대와 무관하게 보장

**보고서 근거**

- 최종보고서 3.3절은 일일 생성 횟수를 한국 시간 자정 기준으로 계산한다고 명시한다.

**수정 전 문제**

- 일일 시작 시각 계산은 `Asia/Seoul`을 사용하지만 작업 생성·수정 시각 일부는 서버 기본 시간대의 `LocalDateTime.now()`를 사용한다.
- 서버가 UTC 등 다른 시간대로 실행되면 한국 자정 기준 조회와 저장 시각이 어긋날 수 있다.
- Jackson 시간대 설정은 JSON 직렬화 설정이므로 `LocalDateTime.now()`의 기준을 바꾸지 않는다.

**수정 대상**

- `backend/src/main/java/com/wakebook/book/domain/HiddenBookJob.java`
- `backend/src/main/java/com/wakebook/book/service/HiddenBookJobService.java`
- 생성 시각, 갱신 시각, 쿨다운을 계산하는 관련 코드와 테스트

**수정 내용**

- 테스트에서 주입할 수 있는 `Clock` 또는 `Instant` 기반으로 시간 계산을 통일한다.
- 한국 자정 경계 계산, 작업 생성 시각, 갱신 시각, 쿨다운 비교가 같은 시간 기준을 사용하게 한다.
- JVM 기본 시간대에 의존하는 직접적인 `LocalDateTime.now()` 호출을 제거한다.

**완료 조건**

- JVM 기본 시간대가 UTC인 조건에서도 한국 자정 전후의 일일 제한이 정확히 동작한다.
- 한국 시간 `23:59:59`와 다음 날 `00:00:00` 경계 테스트가 존재한다.

**구현 결과 (2026-08-19)**

- `HiddenBookJobService`에 테스트에서 주입할 수 있는 `Clock`을 추가하고 운영 기본값은 `Clock.systemUTC()`로 정했다.
- 작업 요청 시 한 번 읽은 `Instant`를 `Asia/Seoul`의 `LocalDateTime`으로 변환해 생성 시각, 7일 쿨다운 기준, 일일 한도 시작 시각에 함께 사용한다.
- `HiddenBookJob`의 직접적인 `LocalDateTime.now()` 호출을 제거하고 생성·상태 변경 시각을 서비스에서 명시적으로 전달한다.
- JVM 기본 시간대를 UTC로 설정한 테스트에서 한국 시간 `23:59:59`는 당일 자정, `00:00:00`은 다음 날 자정을 조회 기준으로 사용하는지 검증했다.
- 생성 시각, 갱신 시각, 쿨다운 기준이 주입한 시계의 동일한 한국 시각을 사용하는지 검증했다.

### [ ] 3.3 도서관별 DB 잠금의 실제 동시성 검증 추가

**보고서 근거**

- 최종보고서 3.3절은 다중 인스턴스 환경에서도 도서관별 중복 수집을 방지한다고 설명한다.

**현재 문제**

- 잠금 테이블과 저장소 호출은 구현되어 있지만 현재 단위 테스트는 저장소 호출 여부만 검증한다.
- 실제 MySQL 트랜잭션에서 두 요청이 동시에 들어왔을 때 하나만 작업을 생성하는지는 자동 검증되지 않는다.

**수정 대상**

- `backend/src/test/java/com/wakebook/book/service/HiddenBookJobServiceTest.java`
- 필요 시 MySQL 통합 테스트 전용 설정과 테스트 클래스
- `backend/build.gradle`

**수정 내용**

- 실제 MySQL 호환 환경에서 두 스레드가 같은 도서관의 작업 생성을 동시에 요청하는 통합 테스트를 추가한다.
- 한 요청만 생성되고 다른 요청은 중복 작업 오류인 `JOB_001`을 받는지 검증한다.
- 잠금 테이블 마이그레이션이 빈 DB에서 정상 적용되는지도 검증한다.

**완료 조건**

- 단위 테스트와 별도로 실제 DB 잠금 동작을 확인하는 반복 가능한 통합 테스트가 존재한다.
- 동시 실행 테스트를 여러 번 실행해도 두 작업이 함께 생성되지 않는다.

## 4. 최종 검증 작업

### [ ] 4.1 실제 외부 서비스 연결 검증

- 저장소에 비밀 값을 커밋하지 않고 MySQL, 도서관정보나루, 알라딘, 카카오, OpenAI 설정을 주입한다.
- 도서관 선택부터 후보 수집, 추천, 재탐색, 비교, 책장 저장, 큐레이션 생성·공개까지 한 흐름으로 확인한다.
- 외부 API 하나가 실패해도 책 단위 실패 격리가 동작하고 전체 작업 상태가 보고서 설명대로 기록되는지 확인한다.

### [ ] 4.2 전체 회귀 검증

- 백엔드 전체 테스트를 실행한다.
- 프론트엔드 프로덕션 빌드를 실행한다.
- 변경된 요청·응답 예시가 `docs/API명세.md`와 일치하는지 확인한다.
- 사용자·사서 권한으로 보호된 API와 작업 조회 소유권 테스트를 다시 실행한다.

## 5. 현재 수정 대상에서 제외할 항목

- 비동기 큐 포화 시 실패 처리, 요청자 본인 작업만 조회, 후보 상위 5,000권 제외, 청구기호 필터, 상세 정보 제공자 순차 대체, 책 단위 외부 API 실패 격리는 현재 구현이 확인되어 신규 수정 항목으로 넣지 않는다. 관련 코드를 변경할 때만 회귀 테스트한다.
